# Chordify — Tab4U Chord Shifter

כלי אישי, מהיר וידידותי לנייד לניהול ספריית שירי גיטרה ישראליים, הצגת אקורדים ומילים, שינוי סולם, שמירת שירים לשימוש offline, וייבוא מבוקר מדפי Tab4U. הפרויקט נבנה בראש ובראשונה עבור Android ו־Samsung Edge, אך הוא פועל גם בדפדפנים מודרניים אחרים.

> מטרת הפרויקט היא לשמור על מיקום האקורדים ביחס למילים, כדי שהשיר יישאר שימושי לנגינה גם לאחר שינוי סולם.

ה־repository הציבורי של הפרויקט נמצא ב־[github.com/Netmi11/chordify](https://github.com/Netmi11/chordify), והגרסה החיה זמינה ב־[tab4uchord-t2tntlcw.manus.space](https://tab4uchord-t2tntlcw.manus.space/).

## יכולות עיקריות

### ספריית שירים

הספרייה מציגה שירים לפי אמן, מאפשרת חיפוש ומיון, ושומרת את תוכן השירים לשימוש אישי. שיר כולל כותרת, אמן, מקור Tab4U, תאריך הוספה, הערות אישיות ושורות תוכן עם אקורדים ומילים.

### תצוגת נגינה

תצוגת השיר שומרת את מיקום האקורד לפני המילה או ההברה המתאימה. קיימת תמיכה בשינוי סולם, קיצור דרך ל־+7, חזרה לסולם המקורי, תצוגת אקורדים בלבד ותצוגת מילים בלבד. קיימת גם תמיכה בסיסית בטאבים כחלק מתוכן השיר.

### תמיכה במובייל

הממשק מותאם למסך צר, לשימוש ביד אחת ולקריאה בזמן נגינה. האפליקציה יכולה להיפתח כ־PWA ממסך הבית של Android, ללא התקנה מחנות אפליקציות.

### גיבוי וסנכרון

הספרייה המקומית נשמרת בדפדפן כדי לאפשר שימוש מהיר ו־offline. כפתור **„סנכרן מהספרייה בענן”** מושך את קטלוג הספרייה המיובאת מהשרת וממזג אותו עם הנתונים המקומיים. המיזוג אינו אמור למחוק שירים או הערות מקומיים, ומשתמש ב־`sourceUrl` כדי למנוע כפילויות.

## שימוש באפליקציה

1. פתח את [כתובת האפליקציה](https://tab4uchord-t2tntlcw.manus.space/) ב־Samsung Edge או בדפדפן Android.
2. בפעם הראשונה, התחבר לאינטרנט והמתן לטעינת הממשק.
3. פתח את **„גיבוי וסנכרון”** ולחץ על **„סנכרן מהספרייה בענן”** כדי למזג את ספריית השרת עם הספרייה המקומית.
4. חפש אמן או שיר, פתח את קבוצת האמן ובחר שיר.
5. בתוך השיר אפשר לשנות סולם, לחזור למקור, להציג מילים בלבד או להשתמש בתצוגת האקורדים.
6. כדי לשמור זמינות במצב טיסה, פתח מראש את השירים הרצויים כשהמכשיר מחובר לאינטרנט.

### הוספה למסך הבית

ב־Samsung Edge פתח את כתובת האפליקציה, פתח את תפריט הדפדפן ובחר **Add to home screen / הוסף למסך הבית**. לאחר ההוספה אפשר לפתוח את Chordify מסמל במסך הבית כמו אפליקציה. אין למחוק את נתוני האתר אם רוצים לשמור את הספרייה המקומית.

## סנכרון הספרייה

הסנכרון מיועד למקרה שבו מסד הנתונים מכיל שירים חדשים, אך דפדפן מסוים עדיין מציג ספרייה מקומית ישנה. התהליך הוא מיזוג, לא החלפה:

| רכיב | התנהגות |
|---|---|
| שיר שכבר קיים מקומית | נשמר, כולל הערות מקומיות |
| שיר שמגיע מהקטלוג | נוסף אם אין מקור זהה |
| מקור עם אותו `sourceUrl` | אינו נוסף פעם נוספת |
| מצב טעינה | מוצג בכפתור בזמן המשיכה |
| תוצאת פעולה | מוצגת הודעה עם מספר השירים שנוספו והמצב החדש |
| כשל רשת | הספרייה המקומית נשארת זמינה; יש לנסות שוב כשהחיבור חוזר |

הסנכרון דורש חיבור אינטרנט בפעם הראשונה. לאחר שהנתונים נשמרו מקומית, אפשר להשתמש בשירים שנשמרו ללא חיבור, בהתאם למדיניות המטמון של הדפדפן ולנתוני האתר המקומיים.

## שימוש ללא אינטרנט

Chordify הוא יישום web עם מעטפת PWA ואחסון מקומי. הוא אינו אפליקציית Android native, ולכן פתיחה ראשונה לחלוטין במצב טיסה אינה מובטחת אם האתר לא נטען קודם כשהמכשיר מחובר. הדרך המומלצת היא לפתוח את האפליקציה פעם אחת online, לסנכרן את הספרייה, לפתוח את השירים הרצויים, ורק לאחר מכן לעבור למצב טיסה ולבדוק שהנתונים הנדרשים זמינים.

אם האפליקציה לא נפתחת במצב טיסה, אין לנקות את נתוני האתר. חבר את המכשיר לאינטרנט, פתח את האפליקציה, המתן לטעינה מלאה ובדוק שוב. ניקוי cache או site data עלול למחוק את הספרייה המקומית.

## תוסף ו־Bookmarklet

בתיקיית `extension/` נמצאים קבצי תוסף/סקריפט שמיועדים להוסיף שכבת Chordify מעל דפי Tab4U. התוסף מאפשר להציג כפתור צף קטן בדף ולבצע שינויי אקורדים בלי לעזוב את דף המקור. בתיקיית `extension/` יש README ייעודי עם הוראות ההתקנה והקבצים הרלוונטיים.

ה־Bookmarklet מתאים לדפדפנים שבהם ניתן ליצור סימנייה עם כתובת JavaScript. אם הסימנייה חוזרת מיד לדף או אינה משנה את התוכן, יש לבדוק שהכתובת נשמרה כולה, ללא רווחים או קיצור אוטומטי של הדפדפן. ב־Android מומלץ להשתמש בתוסף/סקריפט של Samsung Internet או בפתרון המתועד בתיקיית `extension/`, בהתאם לדפדפן.

## ארכיטקטורה

הפרויקט משתמש ב־React 19 וב־Vite בצד הלקוח, Express בצד השרת, tRPC להעברת קריאות typed, Drizzle ORM לגישה למסד MySQL/TiDB, ו־Vitest לבדיקות. השרת מספק גם את מעטפת ה־Vite בפיתוח וגם את ה־API של האפליקציה.

```text
Browser / PWA / Edge
        |
        | React + TanStack Query + tRPC client
        v
Express + tRPC router
        |
        +-- library sync and catalog procedures
        +-- Tab4U parsing and normalization
        +-- Drizzle ORM
                    |
                    v
              MySQL / TiDB
```

הנתונים המקומיים והנתונים שבשרת הם שכבות משלימות. השרת הוא מקור הקטלוג המיובא; הדפדפן מחזיק עותק מקומי שמאפשר תגובה מהירה ושימוש offline. כפתור הסנכרון מחבר בין שתי השכבות באמצעות מיזוג, ולא באמצעות מחיקה והחלפה.

## התקנה מקומית

דרישות מוקדמות: Node.js 22 ומעלה, pnpm, מסד MySQL/TiDB נגיש, ומשתני הסביבה שהשרת דורש. אין להעתיק ערכים אמיתיים של סודות ל־README או ל־repository.

```bash
git clone https://github.com/Netmi11/chordify.git
cd chordify
pnpm install
```

בפיתוח יש להגדיר את משתני הסביבה דרך מנגנון הסודות של סביבת ההרצה. שמות משתנים מרכזיים כוללים `DATABASE_URL`, `JWT_SECRET`, `VITE_APP_ID`, `OAUTH_SERVER_URL`, `VITE_OAUTH_PORTAL_URL`, `BUILT_IN_FORGE_API_URL` ו־`BUILT_IN_FORGE_API_KEY`. יש להשתמש בערכים משלך; אין להוסיף קובץ `.env` ל־Git.

לאחר הגדרת מסד הנתונים והמשתנים, הפעל:

```bash
pnpm dev
```

השרת משתמש בפורט שמספקת סביבת ההרצה ואינו צריך להיות מקודד ידנית בקוד. בפיתוח מקומי אפשר לפתוח את כתובת ה־Vite שהוצגה במסוף.

```bash
pnpm test

```

## ייבוא שירים מאושר

ייבוא שירים הוא תהליך מבוקר. אין להסתמך על כותרת חיפוש בלבד ואין להמציא כתובת Tab4U. לכל שיר נדרש מקור מדויק, התאמת אמן וכותרת, תוכן נגינה משמעותי, ובמקרה של חסימת fetch — snapshot HTML שנשמר לאחר פתיחה ואימות בדפדפן.

המריץ הפנימי נמצא ב־`scripts/import-approved-batch.mjs`. הוא עובד ב־dry-run כברירת מחדל, וה־commit מופעל רק באמצעות הדגל `--commit`. כל manifest צריך להיות קטן או שווה ל־10 שירים.

```bash
node scripts/import-approved-batch.mjs \
  --project . \
  --manifest server/import-manifests/example-batch.json \
  --library <LIBRARY_ID> \
  --snapshot-dir server/import-snapshots/example-batch
```

לאחר בדיקת פלט ה־dry-run בלבד, אפשר לבצע commit מפורש:

```bash
node scripts/import-approved-batch.mjs \
  --project . \
  --manifest server/import-manifests/example-batch.json \
  --library <LIBRARY_ID> \
  --snapshot-dir server/import-snapshots/example-batch \
  --commit
```

יש לאמת לאחר כל commit את רשומות השירים, כתובות המקור, מספר שורות התוכן, היעדר כפילויות והסכומים הכוללים. אין לדרוס הערות, תאריכים או רשומות קיימות. מקור חסר, שיר Premium, כותרת שאינה תואמת או snapshot פגום נשארים מתועדים מחוץ לייבוא.

## מסד הנתונים

הפרויקט משתמש בטבלאות `chordshift_songs` ו־`chordshift_song_lines` עבור הספרייה ותוכן השורות. `chordshift_songs` מחזיקה מטא־נתונים, מקור, מזהים ומידע על הספרייה; `chordshift_song_lines` מחזיקה את המבנה המפורק של תוכן השיר, כולל שכבות מילים, אקורדים וטאבים לפי המודל שבקוד.

נתוני production אינם חלק מה־Git repository. סכמה, migrations, manifests ו־snapshots הם קוד ותיעוד; הם אינם תחליף לייצוא נתוני production. אם צריך להעביר גם את הספרייה עצמה לסביבה אחרת, יש ליצור ייצוא נתונים מאובטח ונפרד, בלי להכניס credentials, cookies או כתובת חיבור למסד.

## עקרונות בטיחות

ה־repository הציבורי אינו מקום לסודות. אין להעלות `.env`, JWT secrets, API keys, cookies, session exports, dumps של production או קבצים המכילים פרטי התחברות. לפני commit חדש יש לבדוק `git status` ולסרוק שמות קבצים ותוכן רגיש.

יש לשמור על זכויות השימוש של מקורות חיצוניים. הפרויקט שומר תוכן לשימוש אישי בספרייה פרטית, אך כל משתמש או מפעיל אחר אחראי לבדוק את תנאי השימוש של Tab4U ואת הזכויות הרלוונטיות במדינתו.

אין לשנות את מסד הנתונים באמצעות SQL הרסני ללא גיבוי והבנה של ההשפעה. ייבוא חייב להיות מצטבר, עם dedupe וללא overwrite. בדיקות דפדפן אינן תחליף לבדיקות Vitest, TypeScript ו־build.

## עבודה עם כלי AI נוסף

כלי AI נוסף יכול להתחיל מהקישור ל־repository ולקרוא קודם את הקובץ הזה, את `todo.md`, את `package.json`, את `drizzle/schema.ts`, את `server/routers.ts`, את `server/librarySync.ts` ואת הבדיקות הרלוונטיות. מומלץ לתת לו הוראה מפורשת לשמור על המבנה הקיים, לא לחשוף או לבקש סודות, לא למחוק נתונים, ולהריץ בדיקות לפני ואחרי שינוי.

נוסח מסירה מומלץ לכלי AI נוסף:

```text
זהו פרויקט React + Vite + Express + tRPC + Drizzle עבור ספריית שירי גיטרה.
קרא קודם את README.md ואת todo.md. שמור על תמיכה ב־Android, PWA ו־offline.
אל תחשוף סודות ואל תוסיף קובצי .env. אל תשנה את מסד הנתונים בלי migration מפורש.
לפני שינוי קרא את הקבצים הרלוונטיים; אחרי שינוי הרץ pnpm test, pnpm check ו־pnpm build.
שמור על מיקום האקורדים ביחס למילים ועל מיזוג מקומי ללא מחיקת הערות או כפילויות.
```

ה־repository הנוכחי ציבורי, ולכן כלי AI נוסף יכול לקרוא את הקוד ללא הרשאה מיוחדת. גישה לנתוני production, לסודות ולמסד הנתונים החי אינה ניתנת דרך GitHub ואינה אמורה להיכלל ב־README.

| טקסט או אקורדים אינם נראים | בדוק ערכת נושא, ניגודיות ורוחב מסך; דווח עם צילום מסך וכתובת השיר. |
| שיר אינו מיובא | בדוק מקור מדויק, התאמת אמן/כותרת, `songContentTPL`, snapshot ו־dry-run. |
| תוסף Tab4U אינו מופיע | בדוק שהסקריפט הותקן בדפדפן המתאים ושהכתובת נשמרה במלואה. |
| בדיקות נכשלות | הרץ `pnpm test`, בדוק את שגיאת Vitest ואת `.manus-logs/` בסביבת הפיתוח. |
